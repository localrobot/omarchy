# AI

Omarchy includes launchers for the coding agents below without choosing a default for you. Run a command to install its CLI on first use, then authenticate when prompted. Hermes is the exception: nothing is installed for it on first use, and choosing it installs Hermes Desktop, as _Desktop apps_ below explains.

### Installing and updating agents

Except for Hermes, these agents use mise's lazy installation: the first launch installs the CLI, and later launches reuse it. mise also checks an installed agent for a new release at most once every four hours, just before it starts or in the background at a shell prompt. If that update fails or you're offline, the installed version runs. `omarchy update` updates installed agents with the rest of Omarchy, and `mup` updates mise-managed tools only.

An agent's own updater, such as `claude update`, `codex update`, or an update button in an app, does not update the mise-managed install. `codex update` fails, and `claude update` can report success while installing a separate copy that mise does not track. If you would rather use an agent's native installer and updater, add it to `disable_tools`; see [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools).

To install all configured lazy tools before you need them, run `mise install --include-lazy`. This includes Omarchy's other default CLI tools as well as the agents. See [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) for installing a single tool or using your own installation.

### The default agent

On fresh workstation installs, Antigravity (`agy`) is configured as the default agent. Pick or switch your default agent with `omarchy default agent <name>` or under _Setup > Defaults > Agent_ in the Omarchy Menu (`Super + Space`). Available options include `agy`, `opencode`, and `kimi`.

Once you've chosen, `Super + Shift + Ctrl + A` launches the default agent in a dedicated terminal window. You can also launch it straight into a task with `omarchy agent prompt "Review this project"`. Agents launched this way run unattended in their respective don't-stop-to-ask modes.

There are terminal shortcuts too: `a` runs the default agent inline in the current terminal, while `c` starts OpenCode directly. Theme changes sync to OpenCode and other supported harnesses when you switch the Omarchy theme.

### The agents panel

The top bar has an agents icon. The panel displays active agent subscriptions, usage quotas, and recent rollouts under one roof. Under _Make something_ it offers starter prompts for a new theme, plugin, or app that hand the task to your default agent. Apps are built the way Omarchy's own Hype is, in C++ and Qt Quick, following the omarchy-app agent skill. Left-click the bar icon for the panel, right-click to launch your default agent.

### Several subscriptions

If you pay for more than one Claude, Codex, or Grok plan — a personal Max and a work one, say — Omarchy can keep them all signed in and move between them. Add a subscription with the + in the agents panel, which walks you through it right there, or with `omarchy agent account add claude Work` (or `codex`, or `grok`). It installs the CLI if it's missing. The first account for a provider signs in through your normal browser, right where the CLI always looks. Every one after that signs in through a private window, so the account your browser is already signed in to doesn't get picked up by mistake; sign in there as the account you're adding, and close any private window you already had open first. Never log out of the CLI to do this: logging out revokes the saved sign-in, and that account would have to be added again.

To copy your subscription logins to another Omarchy machine over SSH, run `omarchy agent account copy user@laptop`. The sender supplies a temporary receiver when the destination does not have one installed, so older Omarchy machines can receive accounts without an update. Installed receivers take precedence. This copies all Claude, Codex, and Grok subscriptions; add provider names to select them, as in `omarchy agent account copy laptop claude`. Account names and command IDs match the source, including accounts already present on the destination. Unrelated destination accounts receive a numeric suffix if their names conflict, and settings, skills, plugins, and conversation history stay local to each machine.

Existing destination credentials are kept. A source account already signed in there has its name synchronized without replacing its credentials; other accounts are added alongside it. To replace saved credentials for matching accounts, use `omarchy agent account copy --replace laptop claude` after quitting that account's sessions on the destination. A fresh destination also gets the source's active account and switching preferences; an established destination keeps its own.

Credentials travel through SSH and are stored in private files on the destination, so copy only to machines you trust. This is a one-time copy, not ongoing synchronization. Codex refresh tokens can be rotated by another machine, leaving a copied login in need of renewal; separate sign-ins remain the most reliable choice for simultaneous use on several machines. See [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth).

One account per provider is active, and every new session starts as it: `cx`, `cy`, a plain `claude`, `codex`, or `grok`, anything launched through `omarchy agent`, and scripts or editors that find the CLI on `PATH`. Switch with `omarchy agent account use work` (and back with `omarchy agent account use main`), or in the panel by pressing an account's number and then `Enter` (or clicking its Use button). Sessions that are already running stay on the account they started with. Conversation history, settings, skills, and plugins are shared across accounts, so `claude --continue` in the same folder picks up where you left off on the new account.

With more than one account, the panel shows each account's limits side by side, with the active one marked. By default Omarchy notifies you when the active account passes 95% of a limit, and clicking the notification switches to the account with the most headroom. Hover an account's line in the panel and click the Autoswitch that appears beside Use (or press `m`), or run `omarchy agent account mode auto`, to have it switch on its own instead; while it's on, Autoswitch takes Use's place, and clicking it again goes back to notifying. Add a number to change the threshold, as in `omarchy agent account mode auto 90`. If every account is over the threshold, you'll hear about it once, along with which account frees up first. While an active account is within 15 points of its threshold (80% at the default), its limits are checked every three minutes rather than every 15.

`omarchy agent account list` shows every account and its latest limits, `omarchy agent account remove work` forgets one, and `omarchy agent account rename primary Work` renames one (or click an account's name in the panel). These commands work on your default agent's accounts; to reach the other provider, name it first, as in `omarchy agent account use codex side`. The login you already had in `~/.claude` or `~/.codex` is the _Main_ account and stays where it is. An account left unused for more than about eight hours can show _Sign-in required_; click it to sign that account in again right in the panel, or start a session in it, which refreshes the sign-in on its own. MCP servers you had when an account was added come along to it, but ones you add later with `claude mcp add` only reach the account you added them in. Claude Desktop and tools configured with an absolute path to a CLI binary do not follow the switch. An explicit `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, or `GROK_HOME` takes precedence over the selected account.

### Crash diagnosis

Omarchy watches systemd-coredump for process crashes. When something segfaults, you'll get a "Process crashed" notification — click it, and the crash is handed to your default agent along with Omarchy's diagnose-crash skill, which walks the agent through establishing the facts from the core dump and deciding whether the crash is worth reporting upstream. You can also run it by hand against any PID from `coredumpctl list` with `omarchy agent crash <pid>`.

The watching is on by default. Turn it off under _Trigger > Toggle > Crash Capture_ (or with `omarchy toggle crash-capture`) and the notifications stop; `omarchy agent crash <pid>` still works by hand.

Crashes can also be silenced one program at a time, which is what the diagnosis offers you at the end. `omarchy crash mute hyprland` stops the notifications for that program only, `omarchy crash mute hyprland off` brings them back, and `omarchy crash mute` on its own lists what you've muted. It takes the binary's path as happily as its name, so `omarchy crash mute /usr/bin/hyprland` does the same thing. Quote a name with a space in it, as in `omarchy crash mute 'Some App'`. Everything else still notifies, and the muted program still crashes — this hides the reminder, it doesn't fix anything.

### Local LLMs

The workstation runs local inference through upstream `llama.cpp` and `llama-server`, accelerated directly on the dedicated RTX 5060 Ti via CUDA. A user systemd service (`systemctl --user start llama-server`) provides an OpenAI-compatible endpoint at `http://127.0.0.1:8080/v1` that OpenCode, Voxtype, and other tools connect to directly.

### The Omarchy Skill

Agent skills help AI use specific tools in a specific way, and Omarchy ships with a default skill for tailoring the system. Like tweaking your Hyprland config, adjusting the bar, or even creating a new theme from scratch. It's symlinked into the skill directories for Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` and each `~/.hermes/profiles/*/skills`), and the generic `~/.agents/skills` location, so most harnesses pick it up automatically.

But you should treat this skill as experimental. Different models will use it to different effect. It's best to run in plan mode first, so you have an idea of what the agent would like to change. And then be ready to rollback changes or even invoking `omarchy reinstall configs`, if the agent makes a mess of everything.
